# asset-pack-contract

素材包 = **一个坐标空间 + 一组带 bbox 的紧图 + 元数据**。目标：换素材不改代码、改布局不悄悄错位、任何时候可复现。

> **唯一事实源**：素材包的坐标空间、`bbox`、对齐方式（`canvas`/`center`）、尺寸归一化口径、帧号索引契约，**以本文为准**。
> 下游 `lip-sync-pipeline`（换口型素材）、`opentoonz-headless-render`（出图与渲染）只讲"怎么用"，不自立口径。

---

## 适用场景

| 触发条件 | 说明 |
|---|---|
| 美术素材要能"换装"（AI 新素材替换旧素材） | 驱动/渲染只认契约 |
| 素材来自不同来源（PSD / AI 生成图 / 图表素材） | 坐标空间与对齐方式不同 |
| 换素材后出现错位、大小不匹配、嘴/眼对不上 | 对齐与归一化问题 |
| 需要跨视频一致的"角色定妆" | 冻结 + 版本 + 质检 |

| 不适用 | 原因 |
|---|---|
| 一次性草图，不复用 | 契约成本高于收益 |
| 只做单张静态图 | 无驱动需求 |

## 1. 包结构与契约

```
<role>_v1/
├── meta.json      space(坐标空间) / reference_bbox / layers[bbox·parent·pivot·motion]
│                  / head{bbox} / mouths{files·bbox·cropped·align·scale·anchor} / performance / roi
├── reference.png  同空间下的整幅角色（定位基准）
├── head.png       头层（"嘴/眼在脸上"校验用）
├── layers/<层>.png   各部件
└── mouths/NNNN.png   各口型帧（**按帧号命名**，同一裁剪框 → 逐帧对齐）
```

**三条硬性契约**

| 契约 | 规则 | 为什么 |
|---|---|---|
| 紧图 + bbox | 包内每张图都是"裁剪到自身内容的紧图"，并在 meta 里记它**在包空间的位置** `bbox` | 定位只依赖 bbox，不依赖图案自身画布 |
| `cropped` 标记 | 紧图 `true`；整幅出图 `false`（解码后需按 bbox 再裁） | 两种来源混用会导致整体错位（实测偏差 57 万像素） |
| 按帧号索引 | 口型/表情列表装**全部帧**（含未使用的），下标 = 帧号 | 时间轴写的是帧号，不能只装用到的子集 |

## 2. 坐标空间与定位公式

```
meta.space 声明空间（相机参数 或 图像画布尺寸）
定位一律在"设计空间"（= 目标渲染像素）里算：
  k = 目标高 / (reference_bbox 高)
  元素设计坐标 = 目标左上 + (元素 bbox − reference_bbox) × k
最后再映射回场景坐标 → 素材来源与场景解耦
```

## 3. 对齐方式（外部素材的关键分歧）

| 方式 | 适用 | 规则 |
|---|---|---|
| `canvas`（画布对齐） | 素材本来就是为该角色画的（位置有意义） | 按 `bbox` 左上角落位，`scale=1` |
| `center`（中心对齐） | **图表类素材**（每张画在图纸固定位置，位置无意义） | 按 `anchor` 中心落位 + `scale` 归一化 |

**尺寸归一化口径**：用**被用形状的宽度中位**配比（不要用整体外框——会被最宽形状/水平错位撑大；实测同一对比下外框法偏大 10%）。

## 4. 质检门槛（自动）

用技能自带脚本跑，逐条手查会漏项：

```bash
python scripts/asset_qa.py --pack path/to/<role>_v1 [--tol 2]
python scripts/asset_qa.py --mouths <目录> --roi x0,y0,x1,y1     # 只查变体对齐
```

- [ ] `meta` 必备字段齐全；文件与 meta 一一对应
- [ ] 每层 bbox 存在且位于包空间内
- [ ] 每层无"小碎块"（孤立小块 <2% 面积）——提示性，最终看合成 IoU
- [ ] **分层合成对位**：用 bbox 合成 vs 参考图，alpha **IoU ≥ 0.98**
- [ ] 变体（口型/表情）：**ROI 外零改动**、变体互不相同、无空变体
- [ ] 驱动参数（头幅/手势频率/口型开合等）存在
- [ ] 骨骼试摆 ±35° 无露缝（目视）

> ROI 由 meta 提供，且比实际内容留 8–16px 余量（过紧会把正常形状变化误报为越界）。

## 5. 顺序规则（最容易埋雷）

```
改了布局(layout)/相机 → 必须：重建 rig（层出图）→ 重新打包 → 再烘焙驱动帧
否则层图与参考图来自不同相机 → 合成 IoU 掉到 0.66、画面整体错位
建议：驱动产物写"布局指纹"，场景侧检测到不一致就提示重烘焙
```

## 6. 禁止事项

| 禁止 | 说明 |
|---|---|
| 用素材自身的画布坐标定位图表类素材 | 会飞出画面/落到脸外 |
| 用整体外框做尺寸配比 | 偏大（实测 10%） |
| 只装"被用到"的帧却按帧号索引 | 越界崩溃 |
| 打包时先删目标再校验输入 | 输入缺失时把成品删成半成品（实测事故） |
| 源就是包自身时还去"重打包" | 循环依赖；包即唯一来源应跳过 |
| 换素材后不做逐帧等价性验证 | 错位/大小问题会一路带到成片 |
