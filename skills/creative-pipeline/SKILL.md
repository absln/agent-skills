# creative-pipeline

## 执行步骤

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1 需求确认 | 交付形态、载体规格、范围、语言、风格 | 需求记录（写入项目约定位置） |
| 2 勘察 | 工具版本、素材结构、可用参数与限制，**以实测为准** | 勘察结论（含失败与限制记录） |
| 3 方案 | 技术路线、参数契约、风险清单、待确认项 | 方案 → **用户确认后**方可执行 |
| 4 制作 | 先打通最小闭环，再批量推进 | 中间产物 |
| 5 交付 | 交付件 + 参数记录 + 再现方式 | 交付件 + 交付说明 |

## 门禁（不可跳步）

1. 步骤 3 方案未获用户确认，**不得进入步骤 4 制作**。
2. 步骤 2 勘察结论必须来自**实际运行或打开文件核对**，禁止凭经验断言。
3. 单步失败当即报告失败现象与已排除项，不得继续堆叠后续步骤。
4. **失败产生的半成品必须显式标记或删除**，不得混入后续产物，更不得进入交付件。

## 红线摘要（每步必须满足）

**产物分级**（步骤 1 定、步骤 4 守）——按级别分目录存放，不得混级：

| 级别 | 权限 |
|------|------|
| 源素材 | **只读**，禁止写入 |
| 加工件 / 工程文件 | 读写 |
| 中间产物 / 成品 | 读写，**可覆盖重建** |
| 交付件 | **只增不改** |

> "只增不改"**只**适用于交付件；中间产物与成品应当随重建覆盖。

**素材**——源素材只引用不修改；加工件命名体现「来源+用途」；建立清单记录来源/许可/加工链；**许可不明不得对外公开**（提交、演示、发布均算）；占位素材必须显式标记且不得进交付件。

**参数契约**（步骤 3 定）——载体规格与尺寸、精度/公差、时长或页数、格式与编码、工艺参数（材料、工艺限制）确认后写入项目约定位置，改动需用户同意；每个取值标注依据（**实测 / 参考文档 / 用户指定**），无依据标「待确认」；禁止散落的、未登记的魔法数字。

**可复现**——记录工具名与**版本**；影响结果的非确定性因素必须显式固定或说明，**未说明前的结果不得作为交付依据**；可复现按产物类型判定：

- 生成型：同输入产出**等价结果**
- 含时间戳/唯一标识的二进制容器（工程文件、压缩包）：**比对关键量**（结构、数量、尺寸、元素清单），**不以字节哈希为判据**
- 含人工判断的：须**能解释差异**
- 状态累积型工程文件（后步依赖前步写入的状态）：必须存在「从零重建」路径并记录

**交付验收**（步骤 5）——交付件清单 + 契约参数记录 + 来源与许可 + 再现方式（含人工步骤）；自检五项：参数一致、关键量可复现、无占位素材、无失败半成品、无未许可素材；平台/署名/对外提交/公开发布**不由 Agent 自行决定**。

**禁止**——覆盖源素材｜编造规格参数｜把「推测可用」写成「已验证支持」｜跑不通粉饰为「已完成」｜需求或方案未确认就产出｜产物错级｜同一事实（名称/参数/尺寸）在脚本、注释、文档各写一份且未登记同步。

## 与其它技能的关系

具体工具做法在步骤 4「制作」按需触发，本技能只管顺序与门禁：

| 载体 | 技能 | 典型触发 |
|------|------|---------|
| PPT | `pptx-generation` | 答辩/汇报/路演/培训 PPT、Markdown 大纲转 pptx |
| Word 文档 | `docx-generation` | 报告、题注、自动目录、中文字体排错 |
| 图示 | `drawio-skill` | 架构图、ERD、UML、时序、C4、BPMN |
| CAD 建模 | `freecad-headless` | 参数化实体、布尔、齿轮、刻字 → FCStd/STL |
| 3D 打印 | `bambu-printable` | 3MF/STL 水密、负实体布尔、1:1 烘焙 |
| 文字转语音 | `edge-tts` | 配音 mp3、多语种音色、语速调节、字幕导出 |
| 说话人分离 | `speaker-diarization-cn` | 对话音频切成「谁在何时说」、分轨 |
| 口型动画 | `lip-sync-pipeline` | 音频→口型帧序列→驱动角色、加表情动作 |
| 场景渲染 | `opentoonz-headless-render` | tcomposer 批量渲染 .tnz、逐帧像素验收 |
| 素材包契约 | `asset-pack-contract` | 换装素材的紧图/bbox/坐标空间/质检门槛 |

> 格式解析（读 PDF/Word/PPT/图片）用 `file-parser`；跨多种载体的深度调研用 `deep-research`。
> 若任务属于**软件系统**开发（需求→设计→任务→编码），不用本技能，走 `system-design` / `system-development`。
