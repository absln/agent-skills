# OpenToonz 无头渲染踩坑全表（含证据）

> 来源：本项目 M2/M4 阶段实测（OpenToonz 1.7.1，`tcomposer.exe`）。
> 每条都写明**现象 → 根因 → 处理**，可作为排查清单。

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | `tcomposer` 退出码 0、无产物、CPU 空闲、无限挂起 | **cwd 不是 OpenToonz 安装根**。当前工程记录在 `stuff/profiles/env/<用户名>.env`，且是**相对安装根**的路径（如 `stuff\sandbox\sandbox_otprj.xml`），cwd 不对时解析不到，程序在 Qt 事件循环里空转（线程全在 ntdll 等待，无模态框） | 一律 `cwd=安装根`。诊断法：`psutil` 采样线程 RIP + 枚举窗口 + 追句柄（挂起时从未打开 .tnz/.psd） |
| 2 | 报 `Undefined: "SOFTWARE\OpenToonz\OpenToonz\TOONZROOT"` | 缺注册表项（本机无 OpenToonz 注册表键） | 命令行显式传 `-TOONZROOT` |
| 3 | `<path>` 写成 `D:/a/b.png` 或相对路径 → 不渲染 | 正斜杠被当作**相对路径** | 一律反斜杠绝对路径：`D:\a\b.png` |
| 4 | 单张 `calib.png` 不渲染（连字节相同的改名拷贝也不渲染） | raster level 必须解析到**编号序列**：路径 `name..png` ↔ 文件 `name.0001.png`。`V1.0001.png` 能渲染正是因为它本身满足序列模式 | 写序列文件；tnz 路径写 `name..png` |
| 5 | 只改 level 的 `name` 不改 `path` → 单列渲染出**整幅 PSD** | 图层级 level 的路径必须带图层标记 | `girl.psd` + 层 `Head` ⇒ `name="girl#Head"`，`path="...\girl#Head.psd"` |
| 6 | 层帧序列（`#frames`）第 2 帧起全空 | 路径没带 `#frames` | ⇒ `name="口型#frames"`，`path="...\口型#frames.psd"` |
| 7 | 某一层**完全不出现**（含"合图缺帽子"） | `<meshColumn>`（网格变形列）会把**紧邻其左侧的 levelColumn 整列吃掉**（网格 level 文件缺失时） | 生成场景时删除 meshColumn |
| 8 | 覆盖关系与预期相反 | 列的前后关系 | 实测：**最左列在最底层**（右列覆盖左列）→ 需要"盖在上面"的列靠右 |
| 9 | 退出码 0 但画面缺元素 | 缺素材/路径不匹配会被**静默跳过** | 验收必须查像素（尺寸、alpha、与设计图比对），不能只看退出码 |
| 10 | `-range 0 4` 只得到 4 帧且编号 0001–0004 | `-range from to` **不含 `to`**；输出编号 = 场景帧 + 1 | 按此换算 |
| 11 | 删空所有列后解析失败 | xsheet 不允许空列 | 改列引用，不删列；填充列指向自建真空白序列 |
| 12 | 相机取景与预期差很多 | dpi=72 时窗口（画布像素）= `cameraSize × 72`；**相机中心是固定偏移**，不等于画布中心 | 用色标实测 `render = canvas×s + b`，不靠推算 |
| 13 | 想一次导出多个元素（层/口型/合图） | — | 「接触表法」：一帧一个元素 + 显式 cells；一次调用即可 |
| 14 | bash 里 `cmd \| tail; echo $?` 拿到 0 | 取到的是 `tail` 的退出码 | 重定向到日志文件，再查 `$?` |
| 15 | 进程锁住工程目录，重命名/删除报 WinError 5 | 残留 `tcomposer.exe` 持有句柄 | 先 `taskkill` 再动目录 |

## 素材出图与坐标

- **接触表法**（推荐）：把要出的元素排成"第 f 帧显示元素 f"，一次 `tcomposer` 调用拿到全部；
  返回的每帧紧 bbox 就是该元素在**该相机空间**的位置和尺寸，后续用它做定位。
- **定位公式**（在"设计空间"= 目标渲染像素里算，最后映射回画布）：
  `k = 目标高 / 参考 bbox 高`；`设计坐标 = 目标左上 + (元素 bbox − 参考 bbox) × k`。
- **等价性验证**：同一素材走两条不同路径（现推 vs 素材包）时，逐帧 md5 必须一致——这是最省事的回归证据。
