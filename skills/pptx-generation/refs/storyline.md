# 汇报叙事结构（先写结论，再排页面）

> 版式决定「好不好看」，叙事决定「有没有用」。`pptx-generation` 负责把内容排进 16:9，
> 本文件负责在排版之前先把**内容组织成一条能推动决策的线**。
> 提炼自 data-storytelling（Setup → Conflict → Resolution），已按汇报场景裁剪。

---

## 1. 一句话结构

```
铺垫（基线） → 冲突（问题/机会） → 解法（洞察 + 建议）
```

三段的篇幅比大约 **2 : 3 : 5**。多数汇报失败在"铺垫占了 6 成、建议只剩 1 页"。

## 2. 页面顺序（不是目录顺序）

| 序 | 页 | 内容 | 判据 |
|----|----|------|------|
| 1 | 钩子 | 一个反直觉的数字或结论 | 观众愿意继续听 |
| 2 | 背景 | 起点、范围、口径 | 让数字可被信任 |
| 3-4 | 冲突 | 现状与目标的差距，逐层逼近 | 每页只推进一个论点 |
| 5 | 关键洞察 | 为什么差距存在（归因） | 一页一句话能说完 |
| 6-7 | 方案与影响 | 做什么、预期收益、代价 | 有数字、有时间 |
| 8 | 决策请求 | 要谁、在什么时候、批什么 | 明确到"批 X 万 / 定 Y 方案" |

## 3. 三种可套的叙事骨架

| 骨架 | 适用 | 段落 |
|------|------|------|
| 问题-解法 | 立项、要资源、故障复盘 | 背景 → 问题 → 洞察 → 方案 → 预期 → 行动 |
| 趋势 | 季度/年度回顾、市场分析 | 我们从哪来 → 变了什么 → 转折点 → 洞察 → 往哪走 |
| 对比 | 选型、A/B、区域差异 | 问题 → 并列对比 → 归因 → 建议 → 风险对冲 |

## 4. 标题要写结论，不写栏目名

| ❌ 栏目式 | ✅ 结论式 |
|----------|----------|
| "数据概览" | "解析成功率从 82% 提到 96%，缺口只在扫描件" |
| "问题分析" | "三个瓶颈里两个已解，剩 OCR 准确率卡在 0.52" |
| "下一步计划" | "需批准 2 人月，把扫描件置信度抬到 0.8 以上" |

一页一个论点：标题就是论点，正文只是证据。读标题串起来应该就是一篇完整报告。

## 5. 三条视觉技法

| 技法 | 做法 | 用在 |
|------|------|------|
| 渐进揭示 | 同一张图分 3 步出现（基线 → 变化 → 结论），不要一上来全元素 | 趋势、归因 |
| 对比 | 左右两栏同一尺度、同一配色体系，只变一个变量 | 方案对比、区域对比 |
| 批注 | 在图上直接标"这里拐了""这段是异常"，代替口头解释 | 关键拐点 |

配套约束：一页一个焦点；强调色只给 1–2 个元素（与 `refs/layout-guide.md` 的配色纪律一致）。

## 6. 常见叙事病

| 病 | 症状 | 药 |
|----|------|-----|
| 数据倾倒 | 8 页图表，没有一句结论 | 每页先写标题结论，再决定要不要这页 |
| 铺垫过长 | 前 5 页讲背景 | 背景压到 1 页，细节进附录 |
| 归因缺失 | 只说"涨了/跌了" | 一定回答"为什么"，并给可验证的证据 |
| 请求模糊 | "希望领导支持" | 写清要什么决定、什么时候要 |
| 无法追问 | 数字没有口径 | 每页角标注明数据源与统计口径 |

## 7. 与其它技能的衔接

- 版式、坐标、容量：`refs/layout-guide.md`
- 生成 `.pptx` 与质检：本技能 `scripts/deck.py`、`scripts/inspect_pptx.py`
- 图表本身要画成成品图（架构/桑基/瀑布等）：`diagram-design`
- 数据解析与口径核对：`file-parser`（带置信度，避免拿 `degraded` 的数字上台）
