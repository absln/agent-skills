## 步骤 3：编码

```
1. 编码顺序：文件结构 → 类型/接口 → 核心逻辑 → 异常处理 → 工具函数 → 入口 → 测试
2. 先写接口签名再写实现；异常路径优先
3. 遵循项目研发规范
4. 按仓库技术栈探测结果加载对应实现层技能（见入口文件「技术栈探测」）
   - **分发顺序**：数据层 → 契约层 → 实现层。涉及接口时，先落 `database-standards` 的字段 / 枚举，再落 `http-api-standards` 的信封 / 错误体 / 分页，最后才写前后端代码；实现层不得自定契约形状
   - **冲突优先级**：实现层（前端 / Python / Rust）与契约层（`http-api-standards`）口径不一致时，以契约层为准，按 bug 修正
5. 敏感信息零容忍（密钥/密码/令牌禁止硬编码）
6. 增量提交（大改动拆多个逻辑独立提交）
```

## 步骤 4：单元测试

```
1. 核心逻辑必须有单测（正常路径 + 边界 + 异常分支）
2. 运行测试，全部通过
3. 对照验收标准逐项确认
```
