# 阶段 1–2：获取任务 + 出方案

> 进入本阶段才读。出口门禁：**实现方案经用户确认**。未确认不得进入编码阶段。

## 步骤 1：获取任务

```
1. 取本人/本项目的待办，或根据需求规划开发任务
2. 按「前置依赖 + 优先级」排序，选可开工的一条
3. 确认该任务的验收标准与关联设计（任务备注里应带 `docs/设计/{文件} §{节}`）
4. 开工时把任务置为进行中
```

> **取数与状态流转归 `task-manager`**：查询见其 §5（`list_tasks`），开工/受阻/完成的状态变更见 §3（`update_task`）；MCP 不可用时按 §12 离线暂存。本节只规定「按什么顺序挑任务」，不重抄工具参数。

## 步骤 2：读设计 + 出方案

```
1. 读关联设计（任务标注的 docs/设计/{文件} §{节}）
2. 理解现有代码架构、命名约定、错误处理模式
3. 分析信息缺口：接口未定？数据模型不明？——列清单，缺则咨询用户
4. 输出实现方案（写代码前必须先出）：
   - 实现思路 / 涉及文件 / 接口签名 / 关键数据流 / 错误处理 / 影响范围
5. 等待用户确认后再编码（禁止跳过方案直接编码）
```

## 本阶段产物

- 选定的 task id + 验收标准
- 实现方案（含涉及文件清单、接口签名、错误处理策略）

## 门禁自检

- [ ] 任务验收标准已明确（不是"大概做一下"）
- [ ] 关联设计文档已读，且能指到具体 §节
- [ ] 信息缺口已列清单并向用户澄清
- [ ] 实现方案已产出并**得到用户确认**
