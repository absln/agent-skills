# 阶段 5–7：集成验证 + 部署 + 提交

> 进入本阶段才读。前置门禁：单测全绿。
> 出口门禁：**端到端通过 + 回归无损 + 任务已完结**。

## 步骤 5：集成验证

```
1. 端到端验证：跑通核心流程（不止单测，验证模块间协作）
2. 发现问题 → 修复 → 重测；新问新统计到项目ISSUES，并关联到对应任务/需求
3. 确认不影响已有功能（回归）
```

## 步骤 6：部署

```
1. 按 README「构建/运行命令」构建发布产物
2. 部署到目标环境并运行验证（/health 探活、核心流程冒烟）
3. 记录部署产物路径与运行方式
```

## 步骤 7：更新任务 + 提交

```
1. 把任务置为已完成（操作见 `task-manager` §3，完成日期由系统记录）
2. 编码中发现设计缺陷 → 回写设计文档（标注「编码反馈」）
3. 集成验证/部署发现的新问题 → 进入下一轮迭代
4. 提交：git add -A && git commit -m "type(scope): 描述"
```

## 本阶段产物

- 集成验证结果
- 部署产物（路径 + 运行方式）
- 任务状态更新记录

## 门禁自检

- [ ] 端到端核心流程跑通（不是只跑单测）
- [ ] 回归通过，已有功能未受影响
- [ ] 部署后 `/health` 与冒烟验证通过
- [ ] 任务已置为已完成并含完成日期
- [ ] 编码中发现的缺陷已回写设计文档
