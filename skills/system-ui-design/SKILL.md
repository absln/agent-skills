# system-ui-design

> 软件研发设计阶段的 **UI 切面**：原型是设计文档的可视化投影——字段与交互取自真实 DDL 和接口契约，禁止编造；视觉取自参考图或成套色板，禁止凭感觉调色。
> 本技能由两份实践合并而成：一份来自实际项目的**字段铁律**（走过设计工具 MCP 直连 → 放弃 → Python 生成 HTML 的选型弯路），一份来自**参考图还原**的 Token 提取与模板资产。

---

## 适用场景

| 触发条件 | 说明 |
|---------|------|
| 概要设计阶段需要界面骨架 | 信息架构 + 页面结构 + 字段占位 |
| 详细设计阶段需要高保真原型 | 字段/枚举/交互取自真实契约 |
| 有参考截图，要还原风格并出设计规范 | 截图 → 设计 Token → 可复用色板 |
| 排查原型不一致 | 原型字段对不上 DDL/接口、原型空壳无真实数据 |

| 不适用 | 原因 |
|--------|------|
| 需求/分析/设计的流程编排 | 用 `system-design` 技能（四阶段门禁 + 五条铁律） |
| 编码/测试/集成/部署 | 用 `system-development` 技能 |
| 可上线的真实应用（路由/状态/接口/构建链） | 走应用开发流程，原型不承担工程化 |
| 只要 PPT / Word 汇报材料 | 走 `pptx-generation` / `docx-generation` |
| 纯图片/插画生成 | 走图像生成 |

> 本技能是 `system-design` 的 UI 切面：`system-design` 规定各阶段产出物、门禁与追溯规则，本技能只负责「设计阶段的 UI 原型怎么做」。

## 核心结论（实战沉淀）

1. **工具选型**：不用 desigma MCP / 专用原型工具，**直接用 Python 脚本生成 HTML**（内嵌 CSS/JS，单文件可双击打开）。理由：desigma MCP 只出结构骨架、无法设置样式、中文必方框，且已被放弃；HTML 方案零依赖、可交互、可版本管理、字段可直接从契约注入。

2. **阶段分工**：
   - **概要设计阶段**：只出**骨架线框**——页面清单、页面间跳转、每页的信息架构（有哪些区块/字段占位），**不填真实字段、不做样式**。
   - **详细设计阶段**：先出**设计规范**（Token + 组件样式，可被执行），再出**高保真 HTML**——字段名、枚举值、下拉选项、按钮、表单校验**全部取自真实 DDL 和接口契约**。

3. **字段来源铁律**：原型里的每个字段、枚举、选项，必须能在数据模型 DDL 或接口契约里找到对应，**禁止编造**。找不到 → 标「待确认」，回指设计文档。

4. **Token 先行**：所有颜色/字号/间距走 CSS 变量，`:root` 定义一次；组件里不写裸色值。视觉取值必须标注来源（图像提取 / 推断 / 待确认），不允许「看着差不多」。

## 步骤 1：概要设计——骨架线框

```text
1. 读需求说明书 + 功能清单，列出页面清单（首页/列表页/详情页/表单页…）
2. 每页画信息架构：区块划分 + 字段占位（只写字段名，不写类型/枚举/样式）
3. 画页面跳转关系（可用 drawio 或文字描述）
4. 不填真实数据、不做视觉样式（灰框 + 占位文字即可）
```

**产出**：`docs/设计/UI原型-骨架线框.md` 或 `.html`（灰框线框）

**门禁**：页面清单与功能清单一一对应，无漏页。

## 步骤 2：详细设计——先定规范，再出 HTML

### 2.1 确认载体参数（缺项再问，不要猜）

| 参数 | 说明 | 默认 |
|------|------|------|
| 参考素材 | 截图 / 现有系统 / 纯文字描述 | 无则按成套色板 |
| 屏幕基准 | 1920×1080 或 2560×1440 | 2560×1440 |
| 页面清单 | 每个页面一句话职责 | 由参考图推断 |
| 交付形态 | 单文件 HTML / HTML+CSS 分离 | 单文件 HTML |
| 交互深度 | 纯静态骨架 / 页面切换 / 含弹窗与表单交互 | 页面切换 |
| 输出目录 | 遵守项目 README / 目录约定；未约定则问 | `docs/设计/` |

一次性问清（合并提问），不要边做边问。

### 2.2 提取 Token（有参考图时）

按 `refs/design-tokens.md` 的采样顺序提取，**每个取值标注来源**：

- `[图像提取]`：从截图直接读到的（背景色、强调色、表头色、文字层级）
- `[推断]`：图上看不出但按规范推导的（hover 态、禁用态、8px 栅格的中间值）
- `[待确认]`：无法判断的（字体是否商用、图标库、字段定义）

提取顺序固定：背景层 → 面板层 → 控件层 → 主色 → 强调色 → 语义色 → 文字三级 → 边框 → 字号阶梯 → 间距节奏 → 组件清单。无参考图时直接取 `refs/design-tokens.md` 的成套色板（深色科技风 / 浅色企业风）。

### 2.3 写设计规范文档

在产出目录写 `design-spec.md`，固定结构（便于团队评审与后续对齐）：

1. 设计风格定位（一句话）
2. 配色（Token 表：变量名 / 色值 / 用途 + 使用规则）
3. 字体（字族、字号阶梯、行高、字重）
4. 间距与栅格（基准栅格、内边距、圆角、栏宽）
5. 组件样式（逐组件：形态、状态、尺寸；多屏时按屏分小节）
6. 适配策略（基准分辨率 + 缩放方案）
7. 组件清单（原型覆盖范围，标明未覆盖项）
8. 待确认项（编号列出，交付时同步告知用户）

规范必须**可执行**：写「表头 40px、13px、#0E3A5C→#123C63 渐变」，不写「表头要有科技感」。

### 2.4 生成高保真 HTML

```text
1. 读详细设计三件套：数据模型 DDL、接口契约（OpenAPI）、关键流程
2. 逐页生成 HTML：
   - 表单字段：input 类型、name、必填/可选 → 取自 DDL 列定义与接口 schema
   - 下拉/单选/枚举：选项值 → 取自接口契约的 enum 或字典表
   - 按钮/操作：动作 → 取自接口的 HTTP 方法 + 路径
   - 列表列：列名 + 字段 → 取自 DDL 列
   - 校验规则：必填/长度/格式 → 取自接口契约的校验
3. 以 assets/prototype-template.html 为起点（已含 Token 变量、页面切换、顶栏/面板/表格/表单基础件），按需增删
4. 字段找不到来源 → 标「待确认」并回指设计文档，禁止编造
```

**产出**：`docs/设计/UI原型-高保真.html`（可交互，字段取自真实契约）

**门禁**：原型每个字段/枚举/操作都能回指 DDL 或接口契约；无凭空字段。

## 步骤 3：自检与交付

1. 跑自检脚本：
   ```bash
   python scripts/check_prototype.py <prototype.html>
   ```
   有 FAIL 必须修；WARN 逐条判断是否接受。

2. 自检清单（脚本覆盖不到的）：
   - 逐页核对：字段名、类型、枚举值、必填项与契约一致
   - 核对跳转关系与流程文档一致
   - 交互（提交/校验/状态切换）与接口语义一致
   - 每个页面都能从导航到达、能回到列表页
   - 表格/表单在基准分辨率下不横向溢出（`min-width` 兜底）
   - 空列用 `—`，不留空白单元格
   - 示例数据分布合理（不要清一色 100%、同一时间戳）
   - 无占位素材（lorem、TODO、待补充）混入交付件

3. 同时交付规范与原型，HTML 开预览。

4. 回复中说明：改了什么、覆盖了哪些组件、**待确认项**、下一步可选方向。不一致处回写设计文档（标注「UI 反馈」）。

## 实现约束

### 必须

- **Token 先行**：所有颜色/字号/间距走 CSS 变量，`:root` 里定义一次；组件里不写裸色值（语义化例外可加注释）。
- **等比缩放**：`html{font-size:clamp(8px,calc(100vw/N),16px)}` + 全量 `rem`（N 为设计宽度/16）。禁止整体 `transform:scale` 与 `zoom`。
- **单文件自包含**：CSS 内联、图标用内联 SVG（stroke 用 `currentColor` 便于状态切换）、JS 用原生，不引 CDN。
- **页面切换**：`data-page` 属性 + 极简 JS 切 `.page.active`，不引入框架。
- **字段注入**：用 Python 读取 DDL/契约后，把字段名、枚举值、校验规则以结构化方式填进 HTML 模板，避免手抄出错。
- **可读性优先**：深色底文字对比度足够；正文不小于 12px（2K 基准下折算后仍可读）。
- **中文编码**：HTML 声明 `<meta charset="utf-8">`，避免乱码（desigma 中文方框的教训）。

### 禁止

| 禁止 | 原因 |
|------|------|
| 大圆角 + 阴影堆叠的「通用卡片风」 | 参考图风格会被抹平，失去还原度 |
| 引入 Tailwind/Bootstrap/组件库 | 单文件约束，且 Token 会被框架默认值污染 |
| 用图片切图冒充组件 | 不可改、不可交互、不可复用 |
| 编造业务字段含义 | 字段不明标「待确认」 |
| 一套 CSS 硬编码多套尺寸 | 缩放必须靠 rem，不靠媒体查询堆砌 |
| 概要阶段就做高保真 | 概要只出骨架线框，高保真下沉详细设计 |

## 常见错误（实战教训）

| 问题 | 现象 | 处理 |
|------|------|------|
| 原型字段与数据模型不一致 | 原型有契约里没有的字段 | 字段回指 DDL/契约，找不到就删或标待确认 |
| 原型空壳无真实数据 | 只有占位符、无枚举/选项 | 从契约 enum/字典表补真实选项 |
| 概要阶段就做高保真 | 概要就填字段、做样式 | 概要只出骨架线框，高保真下沉详细设计 |
| 用专用原型工具绕弯路 | desigma 中文方框、无法设样式 | 直接用 Python 生成 HTML |
| 中文乱码 | 页面显示乱码 | 声明 utf-8 编码 |
| 凭感觉调色 | 色值与参考图偏差大、无法复用 | 按采样顺序提取并标注来源，沉淀成 Token |
