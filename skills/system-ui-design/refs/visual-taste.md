# 审美门禁（拒绝「AI 味」界面）

> `system-ui-design` 的质量门槛保证「字段真实、数据一致、能用」；本文件保证「不难看、不雷同」。
> 提炼自 frontend-design（去 AI 味方法论），按软件系统原型的场景改写。

---

## 1. 先定方向，再写第一行 HTML

动手前用三句话写死方向（写不出来就别开始画）：

| 项 | 要回答 | 反例 |
|----|--------|------|
| 用途 | 谁在什么场景看这个界面 | "给用户用的" |
| 调性 | 从极端里挑一个：极简 / 高密度工业 / 编辑杂志 / 复古终端 / 柔和粉彩 / 奢华克制 | "简洁大气" |
| 记忆点 | 一处让人记得住的设计决策 | 无 |

调性不是形容词堆叠，是**取舍**：极简就砍到只剩层级，工业高密度就敢用小字号和硬边框。

## 2. 明确的禁止项

| 禁止 | 原因 |
|------|------|
| Inter / Roboto / Arial / 系统默认字体当主字体 | 全世界默认长相，一眼 AI |
| 白底 + 紫蓝渐变主视觉 | 模型默认审美 |
| 三种以上主色平均分配 | 等于没有主色 |
| 等宽三列卡片当默认布局 | 通用模板感 |
| 每张卡都加 `box-shadow` + `rounded-2xl` | 阴影堆砌掩盖层级缺失 |
| 圆角 ≥ 16px 到处用 | 与数据密度高的后台界面不搭 |
| 图标+标题+副标题+按钮四件套的居中 Hero | 落地页模板 |

## 3. 正向手法（可落地）

| 维度 | 做法 |
|------|------|
| 字体 | 显示字体（标题）与正文字体分工；中文用「思源黑体/霞鹜文楷」等有性格的家族，数字用等宽或几何体 |
| 颜色 | 一个主色 + 一个强调色 + 中性灰阶梯；全部写成 CSS 变量，禁止散落 hex |
| 留白 | 靠间距比靠边框分块：8 的倍数节奏，块内紧、块间松 |
| 层次 | 用字重、透明度、1px 描边建立层级，少用阴影 |
| 细节 | 一处克制的质感：细网格、噪点、切角、发丝线、微妙的渐变边缘 |
| 动效 | 一次性入场（staggered reveal）优于满地 hover；尊重 `prefers-reduced-motion` |
| 构图 | 允许不对称：主数据区宽、辅助区窄；避免 1:1:1 均分 |

## 4. 与「数据真实」的冲突怎么解

审美好看不能凌驾于正确性：

1. 字段、枚举、状态值必须来自真实 DDL / 接口契约（见 SKILL 步骤 2.1），**不能为了排版整齐编造数据**；
2. 真实数据长短不齐时，用截断 + tooltip / 次级页展示，不要改数据；
3. 空态、加载态、错误态必须真实存在（这三种状态最容易在原型里被省掉）；
4. 装饰性图形（背景网格、光晕）与数据图形要分层，别让装饰遮住数值。

## 5. 三十秒自检

- [ ] 把这页截图和「任意一张 AI 生成的后台界面」并排，能一眼区分吗？
- [ ] 主色是否只有一个，强调色只出现在 1–2 个元素？
- [ ] 所有颜色/字号/间距是否来自设计令牌，没有临时 hex？
- [ ] 字号阶梯有 3 级以上落差（而不是 12/13/14 挤在一起）？
- [ ] 去掉所有阴影，界面还有层级吗？
- [ ] 数字是否等宽对齐（表格右对齐、小数位统一）？
- [ ] 空态/错误态/超长文本三种情况都画了吗？
