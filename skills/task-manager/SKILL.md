# task-manager

> 项目管理 MCP 系统的唯一入口 + 周报/季报/绩效生成器：任务登记、状态流转、工作日志、周报/季报取数与生成、问题溯源（RTM）、数据门禁巡检，一律走 MCP 工具，不再写 `.agents/tasks/TASKS.md`。

## 本文件在技能体系中的角色

**任务相关事实的唯一事实源。** 其他技能只描述「什么时候该做任务动作」，具体字段与状态规则一律回到这里：

| 契约事实 | 唯一事实源 | 编排层角色 |
|---|---|---|
| 任务字段（标题/类型/项目/排期/优先级/依赖/备注）与必填规则 | **§2** | `system-design` 步骤 4 只判断任务拆得够不够格，登记时引用本节 |
| 任务状态机与流转操作（开工/受阻/完成） | **§3** | `system-development` 计划阶段取任务、交付阶段完结任务都引用本节 |
| 调用失败的离线兜底 | **§12** | 任何技能遇到 MCP 不可用都引用本节，不自写兜底 |
| 各阶段编排与门禁 | `system-design`、`system-development` | 本技能不定义流程顺序 |

> 边界一句话：**本文件管「任务怎么记」，编排技能管「什么时候去记」。** 编排技能里出现字段名或状态值清单即为重复定义，应删掉改指针。

## 0. 触发识别（最容易漏的一步）

| 用户输入 | 判定 | 必须动作 |
|---------|------|---------|
| 「今天上午完成 A 项目推进讨论」 | 陈述式工作汇报 → 工作记录 | `list_projects` → `create_task`（若无对应任务）→ `update_task(status="done")` |
| 「XX 项目明天要去现场」 | 计划 → 新建待办 | `create_task`（`todo`，`start_at`/`plan_end_at` 填日期） |
| 「XX 项目卡在等客户反馈」 | 受阻 | `update_task(status="blocked")` + `note` 写阻塞原因 |
| 「上周干了啥」 | 取数 | `list_tasks`（`done_from/done_to`） |

硬性要求：

- **先查后写**：项目 / 成员 ID 必须来自 `list_projects` / `list_users` 返回值，禁止使用记忆或 mapping.md 快照直接写。
- **新建只能 todo**：要表达"已完成"，必须 `create_task` 之后再 `update_task(status="done")`，一步到位做不到。
- **一句话涉及多个项目**：按项目拆成多条任务，或先问归属，但**必须先调用工具**，不允许静默不动作。
- **禁止**：只回「收到」、写 md 文件记录、猜 ID、把已完成的说成待办。

## 适用场景

| 触发条件 | 说明 |
|---------|------|
| 记录每日工作 / 工作日志 | 用 `create_task` 落库，完成态用 `update_task(status="done")` |
| 登记待办 / 研发任务 | `create_task`，状态 `todo` |
| 开工 / 受阻 / 完成 | `update_task` 只传 `status`（不传其他字段） |
| 查询本周 / 本季度做了什么 | `list_tasks` 按 `done_from/done_to` 取数 |
| 确认项目 / 成员 ID | `list_projects` / `list_users`（任务类型是固定枚举，见 `refs/mapping.md` §3，无需查询） |
| 发现问题 / 需求 / Bug | `create_issue` |
| 生成研发周报 / 季报 | 本技能 §6/§7（MCP 取数 → xlsx + md）；无数据时 §8 手工兜底 |

| 不适用 | 原因 |
|--------|------|
| 需求 / Bug 的详细流程 | Issue 状态机详见 `refs/mapping.md` |
| 军方结项合规文档 | 用 `docs-generate-china-standard` 技能 |
| 季度述职 PPT | 用 `pptx-generation`，取数仍走本技能 §5 |

## 前置条件

```
1. MCP 工具已在客户端注册（list_projects / list_tasks / create_task … 共 13 个），按工具名直接调用。
   端点地址、认证方式、API Key 全部由客户端配置托管，Agent 不感知、不接触。
2. 生成周报 / 绩效 xlsx 需 openpyxl（系统 Python 有；server/.venv 没有，跑脚本用系统 Python）
```

> **唯一调用通道 = MCP 工具。** 禁止用 `curl` / `urllib` / `requests` / 自写脚本直连 MCP 端点；禁止读取、索要或写入 API Key、端点 URL、`server/.env`。
> 服务端可能部署在另一台机器上，Agent 既不知道地址也没有凭据——任何"先探活再调用"的写法都无效。
> 工具调用失败（报错 / 超时 / 401 / 连接不上）时，按 §12 写入离线暂存区，恢复后回补。

> 固定口径（任务类型枚举 / 状态机 / 日志分类映射 / 取数区间）**全文见 `refs/mapping.md`**，使用前先读取。
> 项目与成员清单**不在 skill 内维护**，一律实时取自 `list_projects` / `list_users`。

## 执行步骤

### 1. 读口径表

```
先读 refs/mapping.md，拿到：
  - 任务类型（software* / design / ip / daily）枚举与周报分类
  - 状态机、日志分类 → task_type 映射、取数口径
项目 ID / 成员 ID 一律现场取自 list_projects / list_users，不依赖任何固定 ID 清单。
```

> 查项目一律 `list_projects()` **不传 parent_id**（传 `parent_id=0` 只返回顶层主项目，挂在主项目下的子项目会被过滤掉）。
> 用户口头说「某主项目 + 编号」时，编号通常是子项目的内部编号：先 `list_projects` 全量列出，按 `code` / `name` 匹配，匹配不到再问用户。

> ID 以 `list_projects` / `list_users` 实时返回为准，**禁止硬编码或凭记忆填 ID**。
> 任务类型（`software*` / `design` / `ip` / `daily`）是固定枚举，MCP 不提供查询工具，直接取 `create_task` 的 `task_type` 参数说明或 mapping.md §3。

### 2. 登记任务（create_task）

```
create_task(
  title=<必填，一句话说清干什么>,
  task_type=<必填，按分类映射>,
  project_id=<必填，先用 list_projects 查实时 ID；不确定归属就问用户，禁止留空>,
  assignee_id=<可选，先用 list_users 查 ID；不传=未分配>,
  description/deliverable/note=<按需>,
  start_at/plan_end_at=<排期：计划开始 / 计划结束；按需>,
  due_at=<截止日期；与 plan_end_at 同义时不要两个都填>,
  priority=low|medium|high|urgent（默认 medium）,
  predecessors=<前置任务 id 列表；无则空>
)
```

约束：
- `project_id` **必填**：不传 / 传 `None` 直接报「项目必填」，传不存在的报「项目不存在」。归属不明时先问用户，实在无法归类则挂到 `list_projects` 返回的「内部管理 / 日常管理」类项目（按 `name` 匹配，不写死 ID），并在 `note` 写明原因。
- `assignee_id` 可选（不传=未分配），但禁止凭空编造 ID。
- 新建后状态固定为 `todo`，不能在建的时候指定 `done`；要完成必须再调一次 `update_task`。
- `note` 写备注 / 待确认问题（会进周报「说明」列）。
- **字段名以 MCP `create_task` 工具 schema 为准**：本节与 §11 巡检规则（R3/R5 读 `start_at`/`plan_end_at`）必须一致；schema 若只有 `due_at`，改本节并同步巡检规则，不许两套并存。依赖用 `predecessors`（id 列表），不写进 `note` 文字。
- 一条任务只登记一次，不重复建。

### 3. 状态流转（update_task）

```
update_task(task_id=<id>, status="in_progress"|"blocked"|"done")
```

- **只传 `status`**，其他字段未变化一律不传（避免误清空）。
- 进入 `done` 时系统自动写 `done_at`；离开 `done` 时自动清空。
- 受阻：`status="blocked"` 并 `update_task(task_id, note=<阻塞原因/已排除项/需要用户提供什么>)`。

### 4. 记录工作日志

```
日志条目 = 一条 task，完成后流转 done
- 项目相关：挂对应 project_id + task_type 按分类（design/software.*）
- 专利：task_type="ip"
- 其他/日常：task_type="daily"，project_id=内部管理类项目（按 `list_projects` 的 `name` 匹配，不写死 ID）
- 每日"今日完成"逐条建，完成后 status="done"（done_at 自动记录）
```

### 5. 查询与取数（一律用 MCP 工具）

```
list_projects()                                    # 项目（不传 parent_id）
list_users()                                       # 成员
list_tasks(project_id|task_type|status|assignee_id|done_from|done_to|start_from|start_to, offset, limit)
list_issues(project_id|parent_id|type|status|assignee_id|keyword, offset, limit)
```

- 时间格式 ISO：`YYYY-MM-DDTHH:MM:SS+00:00`，区间**左闭右开**。
- 本周做了什么：`done_from=<周一>T00:00:00+00:00`，`done_to=<下周一>T00:00:00+00:00`。
- 下周计划：`start_from` / `start_to` 同理（计划开始时间）。
- 本季度：`done_from=<季度首日>`、`done_to=<下一季度首日>`。
- `limit` 默认 20，取全量需循环翻页（`offset` 递增），直到累计条数 ≥ `total`。
- 名称回填（项目名 / 负责人名 / 类型中文名）在本地用 `list_projects` / `list_users` 的返回结果做映射，**不要为回填再调一次工具**。

> 取数全部通过工具调用完成；不要为了"省 token"去跑本地脚本直连服务端——Agent 没有凭据，也拿不到端点。
> 若某次工具调用失败，按 §12 处理；取数失败时**不要**用对话记忆或上周 Excel 冒充系统数据。

### 6. 生成周报（标准路径：MCP 取数）

> **数据来源是 MCP 任务表**（不是对话记忆、不是上周 Excel）。产物：`周报/{年}/研发周报-{YYYYMMDD}-{姓名}.xlsx` + 同名 `.md`（邮件正文）。
> 系统里有数据走本步骤；系统里没数据退回 §8 手工兜底。两者结果不一致时**以本步骤为准**（每行可追溯 task id）。

#### 6.1 时间边界

```
本周 = 周一 00:00:00 ~ 下周一 00:00:00（左闭右开，UTC）
下周 = 下周一 00:00:00 ~ 下下周一 00:00:00
ISO 格式：2026-03-30T00:00:00+00:00
```

#### 6.2 两个查询

| 周报列 | 查询 | 参数 |
|---|---|---|
| **工作内容**（D 列） | `list_tasks` | `done_from`/`done_to` = 本周区间，`assignee_id` = 本人 |
| **下周工作计划**（F 列） | `list_tasks` | `start_from`/`start_to` = 下周区间，`assignee_id` = 本人 |

> `done_at` 由流转到 `done` 时自动写入、离开 `done` 时自动清空，因此「本周完成」口径稳定。

#### 6.3 字段映射

| 周报列 | 系统字段 | 处理规则 |
|---|---|---|
| A 序号 | — | 从 1 递增 |
| B 任务分类 | `task_type` | 按 §6.4 映射表转中文 |
| C 项目名称 | `project_id` → `list_projects` 的 `name` | 项目必填，不会为空；名称必须与 `list_projects` 返回完全一致 |
| D 工作内容 | `title` + `description` | 每行前缀 `·`，多行用 `\n` |
| E 交付物 | `deliverable` | 原样，空则留空 |
| F 下周工作计划 | 下周区间任务的 `title` | 每行前缀 `·`，无则 `·暂无` |
| G 说明 | `note` | 原样，空则留空 |

#### 6.4 分类映射

| `task_type` | 周报分类 |
|---|---|
| `design` | 方案设计 |
| `software` / `software.*` | 软件开发 |
| `ip` | 知识产权 |
| `daily` | 其他工作 |
| 其它（`dev` 等历史值） | 按 `title` 语义判断，无法判断归「其他工作」并在 G 列标注"分类待确认" |

> 历史周报出现过"算法开发""技术支持""文档编写"等无对应 code 的分类：**不擅自改名**，归入最接近的类并在 G 列注明。

#### 6.5 Excel 模板（实测自历史周报 xlsx，取最近一份作样式样板）

| 区域 | 坐标 | 内容 | 样式 |
|---|---|---|---|
| 标题 | `C2:E2`（合并） | `研发周报` | 宋体 18 加粗，居中，行高 22.5 |
| 姓名标签 | `A4` | `姓名` | 宋体 11，thin 边框，居中 |
| 姓名值 | `B4:C4`（合并） | 当前用户姓名（`list_users` 取） | 同上 |
| 日期标签 | `D4` | `起始日期` | 同上 |
| 日期值 | `E4:G4`（合并） | 如 `3.30-4.3` | 同上 |
| 表头 | `A6:G6` | 序号/任务分类/项目名称/工作内容/交付物/下周工作计划/说明 | 宋体 11，thin 边框，居中 |
| 数据区 | `A7` 起 | 逐行任务 | 宋体 11，thin 边框；D/F/G 左对齐 + 自动换行 |
| 尾注 | `A{n}:G{n}`（合并，n = 最后数据行 + 2） | `研发周报及交付物将作为季度绩效考评以及年度绩效考评的依据！！！` | 宋体 11，无边框，居中 |

**列宽（必须照抄）**：

```python
{'B': 9.4, 'C': 27.73, 'D': 40.88, 'E': 23.87, 'F': 47.0, 'G': 84.75}
```

**行合并规则**：

| 列 | 规则 |
|---|---|
| B 任务分类 | 同分类连续行合并 |
| C 项目名称 | 同项目连续行合并 |
| E 交付物 | 不合并，逐行填 |
| G 说明 | 不合并，逐行填 |

> 排序：先按 B 分类历史顺序（方案设计 → 软件开发 → 知识产权 → 其他工作），再按 C 项目名。
> **尾注行号动态**：按「最后数据行 + 2」计算并合并整行，不硬编码行号。

#### 6.6 执行流程

```python
from datetime import date, timedelta
today = date.today()
monday = today - timedelta(days=today.weekday())      # 本周一
next_monday = monday + timedelta(days=7)              # 下周一
week_end = monday + timedelta(days=4)                 # 本周五（文件名用）
```

1. **确定周期**：文件名 `研发周报-{week_end:%Y%m%d}-{姓名}.xlsx`。
2. **查数据**：`list_tasks` 本周完成用 `done_from/done_to`，下周计划用 `start_from/start_to`（见 §5）。
3. **组装行**：本周完成 → 一行一个任务（工作内容/交付物/说明）；下周计划 → 填入 F 列或追加行。
4. **填下周计划**：默认策略 A——下周任务与本周某行同项目则追加到该行 F 列，剩余无归属下周任务追加为新增行（E/G 留空）；下周为空则每行 F 填 `·暂无`。
5. **写 xlsx**：`shutil.copy` 最近一份历史周报做样式样板 → 取消 A7 起所有合并 → 清空 A7 起值 → 写姓名/日期/数据行 → 合并 B/C 同类连续行 → 写尾注 → 保存。
6. **邮件 md**：按项目分组列要点，项目排序取 `list_projects` 返回顺序（主项目在前、子项目随后），未归类项放最后。

```markdown
# 研发周报（{monday:%Y.%m.%d} - {week_end:%Y.%m.%d}）

{称呼}，您好：

本周主要工作按项目汇总如下：

## {项目名}
- {工作内容要点 1}
- {工作内容要点 2}

下周计划：
- {下周任务 1}
- {下周任务 2}

详细见附件，有任何问题随时联系。

{当前用户姓名}
{职务}
{公司名}
```

#### 6.7 校验规则（生成后必须自检）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 行数 | 数据行数 == 本周完成任务数（或含下周新增行） |
| 2 | 序号 | A 列从 1 连续递增，无跳号 |
| 3 | 分类 | B 列值 ∈ {方案设计, 软件开发, 知识产权, 其他工作} |
| 4 | 项目名 | C 列值与 `list_projects` 返回的 `name` 完全一致，无自造名 |
| 5 | 交付物 | E 列非空行数 == 有 `deliverable` 的任务数 |
| 6 | 下周计划 | 每行 F 列非空（无计划填 `·暂无`） |
| 7 | 尾注 | 尾注行 = 最后数据行 + 2，且 A:G 合并 |
| 8 | 列宽 | B=9.4 C=27.73 D=40.88 E=23.87 F=47.0 G=84.75 |
| 9 | 字体 | 全表宋体 11（标题 C2 宋体 18 加粗） |
| 10 | 可追溯 | 每个数据行对应一条 task id，交付附「行号 ↔ task id」对照表 |

### 7. 生成季报

- 取数：`list_tasks(status="done", done_from=<季度首日>, done_to=<下一季度首日>)`，计划项同理用 `start_from/start_to`。
- 汇总：先出本季度各周周报（复用 §6），再按项目聚合季度任务。
- 生成：复用 §6 的 Excel 模板逻辑与邮件格式；述职 PPT 另走 `pptx-generation`，本步骤只提供取数与数据汇总。

### 8. 手工兜底（MCP 无数据时）

> 仅当系统里没有任务数据时使用：基于上周 Excel 模板延续 + 对话补充，不读数据库。

```
1. 本周结束日期 = 本周五（YYYYMMDD）；上周 Excel = 周报/研发周报-{上周结束日期}-{姓名}.xlsx
2. shutil.copy 上周 Excel → 新文件；更新 E4 为本周日期范围
3. 取消 A7:G26 所有合并、清空 A7:G26 值
4. 延续上周任务（原文照抄，除非用户告知状态更新）+ 补充本周新增
5. 下周计划 F 列从对话提取；上周有计划本周未提完成 → 询问用户
6. 合并 B 列（分类）、C 列（项目名）；A6:G26 设 thin 边框
7. 保存，并生成同名 .md 邮件正文
```

> 兜底产出也放 `周报/` 目录，命名与 §6 一致；一旦系统录入数据，优先走 §6。

### 9. 生成绩效（季度取数 → 套模板 → 只写事实）

> 触发：「生成某季度绩效」「写自评素材」「绩效表填事实」。**Agent 只填事实描述，评分列一律留空由人填。**

> 区间与文件命名、六个考核项的取数口径、写入坐标（`季度绩效考核` sheet，A1:L19）见 `refs/performance-and-rtm.md` →「生成绩效」

#### 硬性规则

| 规则 | 说明 |
|------|------|
| 不代填分数 | C/D/G–J 一律留空；写了等于伪造考核结果 |
| 不推断无数据项 | 团队协作、考勤无系统数据 → 明确写「无系统数据」 |
| 不跨季度 | `done_at` 不在区间内的任务不得计入 |
| 可追溯 | E 列事实必须带 task id 或周报文件名 |
| 不改公式 | 合计行 `=C3*0.6+...` 保留，不重算不覆盖 |
| 不改权重 | K 列以模板为准 |

> 生成后必须按 **7 条校验**自检（分数留空 / E 列 6 项齐 / 可追溯 / done_at 在区间 / 合计公式未改 / 权重未覆盖 / 文件名月份=季末月）见 `refs/performance-and-rtm.md` →「绩效生成后校验」

### 10. 问题溯源与变更影响（RTM）

> 触发：「这个需求做到哪了」「改了需求会影响哪些任务」「出个需求追踪矩阵」。

> 需求树结构、RTM 生成步骤、变更影响分析流程见 `refs/performance-and-rtm.md` →「问题溯源与变更影响（RTM）」

#### 硬性规则

| 规则 | 说明 |
|------|------|
| 只读 | 只输出清单，**不改任何数据**；要改由用户确认后逐条 `update_task`/`update_issue` |
| 不猜影响 | 无 `refs`/`predecessors` 关联的对象不臆测影响 |
| 含已完成 | 变更影响必须包含 `done` 任务（需回归），不能只看未完成 |
| 标存量 | 存量未绑定单独标注，不混入真实缺口 |

### 11. 数据门禁巡检（存量体检）

> 触发：「检查数据有没有问题」「巡检一下」「周报前先体检」。**只报告，不修数据。**

七条规则的判据摘要：

| 编号 | 规则 | 一句话判据 | 严重度 |
|---|---|---|---|
| R1 | 必填缺失 | 标题 / 项目 / 类型为空，或已完成却无完成时间 | 高 |
| R2 | 分类非法 | 类型或状态不在枚举内 | 高 |
| R3 | 状态与时间矛盾 | 完成态与完成时间不一致、排期起止倒挂 | 高 |
| R4 | 长期停滞 | 进行中且超过 `--days`（默认 14）未更新 | 中 |
| R5 | 逾期未流转 | 计划结束已过但仍未完成 | 中 |
| R6 | 关联断裂 | `refs` / `predecessors` 指向不存在对象 | 中 |
| R7 | 批量补录嫌疑 | 同项目 ≥3 条完成时间同秒（只提示，不算错） | 低 |

**执行要点**：`list_*` 全量翻页取数 → 本地逐条判定 → 输出「汇总 + 明细」两表，证据列写具体字段值。**全程只读**，不得调用任何 `create_*` / `update_*`；修数据须用户确认后逐条执行。

> 完整判定条件、执行步骤、输出格式与四条边界见 `refs/inspection.md`。

### 12. 离线暂存与回补（工具调用失败时）

> 触发：**任何一次 MCP 工具调用失败**（报错 / 超时 / 401 / 连接不上 / 客户端未注册工具）。
> 不设"先探活"步骤——Agent 不知道端点也不持有凭据，探活必然失败；只以工具真实返回为准。

#### 12.1 判定与动作

| 工具返回 | 判定 | 动作 |
|---|---|---|
| 正常返回 | 可用 | 按 §1–§11 正常执行，**不写任何本地文件** |
| 报错 / 超时 / 401 / 连接失败 | 不可用 | 把本次操作写入离线暂存区（12.2），并在回复里明确「已暂存 N 条，待服务恢复后回补」 |
| 参数校验类报错（如「项目必填」「项目不存在」） | 可用，是调用写错了 | **不入暂存区**，改参数重试 |

#### 12.2 暂存区文件与格式

```
.agents/tasks/TASKS.md    任务操作（create_task / update_task）
.agents/tasks/ISSUES.md   问题操作（create_issue / update_issue）
```

> 这两个文件只有表头说明，**不是台账**；目录内不设 README（职责已在本节说明）。

一条操作 = 一个二级标题块，字段固定：

```markdown
## [PENDING] a1b2c3d4 完成A项目方案评审
- id: a1b2c3d4
- op: create_task
- created_at: 2026-10-20 15:30
- reason: 连接被拒绝
- payload:
  ```json
  {"title": "完成A项目方案评审", "task_type": "design", "project_id": 101}
  ```
```

- `id` 8 位十六进制，回补时用于查重（幂等），不重复建单。
- `[PENDING]` 待回补；`[SYNCED]` 已回补（留痕，可删）。
- 只追加，不改已有块；同一件事只入队一次。

写入用 `scripts/outbox.py`（**纯本地文件读写，不联网、不碰 MCP**）：

```bash
python #/skills/task-manager/scripts/outbox.py add --file tasks --title "完成A项目方案评审" --payload '{"title":"完成A项目方案评审","task_type":"design","project_id":101}' --reason "连接被拒绝"
python #/skills/task-manager/scripts/outbox.py list
```

> 手写 markdown 也可以，格式必须与上面一致。

#### 12.3 回补

回补**由 Agent 用 MCP 工具逐条重放**，不跑任何脚本、不直连 HTTP：

1. `outbox.py list` 读出全部 `[PENDING]`，按 `create_task → create_issue → update_task → update_issue` 排序（先建后改）。
2. 逐条调用对应 MCP 工具，`payload` 原样作为参数。
3. **建单前查重**：同 `project_id` + 同 `title` + 未完成（task）/ 未关闭（issue）已存在 → 跳过建单，视为已回补。
4. 成功 → `outbox.py remove --id <id>` 删除该条；失败 → `outbox.py mark --id <id> --status PENDING` 保持待补，并把 `reason` 更新为本次失败原因。
5. 输出对账表（成功 / 跳过 / 失败 / 格式损坏），贴给用户。

> 全部清空后 `.agents/tasks/TASKS.md`、`ISSUES.md` 只留表头，**不得**把它们当台账继续维护。

#### 12.4 幂等与边界

| 规则 | 说明 |
|---|---|
| 查重键 | 同项目 + 同标题 + 未完成（task）/ 未关闭（issue），命中即跳过建单 |
| 不重复入队 | 同一操作已在 `[PENDING]` 中，不再追加 |
| 不伪造成功 | 工具失败时禁止说"已登记"；必须说明已暂存 |
| 不用暂存区当台账 | 暂存区只是待办队列，权威数据永远在 MCP |
| 不写脚本直连 | 禁止写/跑任何调用 MCP 的 Python 脚本（含 `requests` / `urllib` / `httpx` / MCP SDK）；回补只用工具 |
| 取数失败不兜底成记忆 | 周报/绩效取数失败 → 告知失败，不得用对话记忆冒充系统数据 |

## 常见错误

| 问题 | 现象 | 处理 |
|------|------|------|
| 流转状态报「负责人必填」 | 旧版 MCP 把未传字段显式传 None | 已修复；仍只传 `status`，不传 None |
| 传了不存在的 project_id/assignee_id | 建 task 报错 | 先 `list_projects` / `list_users` 查实时 ID |
| 建 task 报「项目必填」 | 未传 `project_id`（该字段已改为必填） | 查 `list_projects` 补上；归属不明问用户，或挂内部管理类项目并在 note 说明 |
| 建 task 报「项目不允许清空」 | `update_task` 传了 `project_id=None` | 调整归属时传真实 ID，或干脆不传该字段 |
| 时间区间写错 | 取数为空或多一周 | 用 ISO 格式、左闭右开，`done_to` 取下周一零点 |
| 日志与任务两套并存 | 同一件事既写文件又建 task | 一律走 MCP，文件仅存档不新增 |
| 周报是空表 | 本周没有 `done_at` 落在区间内的任务 | 告知用户「本周无已完成任务」，不要伪造；或走 §8 兜底 |
| 行数比预期多 | 任务反复改状态，`done_at` 多次写入 | 检查 `done_at` 是否在区间内，属正常 |
| 分类显示 `dev` | 历史数据用了非字典 code | 按 §6.4 映射，G 列标注 |
| MCP 工具调用报错 / 超时 / 401 / 连接失败 | 服务端不可达或凭据失效 | **不要**改用 curl 或脚本直连；按 §12 写入离线暂存区，并告知用户「已暂存 N 条，待服务恢复后回补」 |
| 尾注位置错 | 硬编码了行号 | 改为「最后数据行 + 2」动态计算 |
| 合并单元格报错 | 先写值后合并，或合并区域重叠 | 先 unmerge 全部，写值，再按锚点合并 |
