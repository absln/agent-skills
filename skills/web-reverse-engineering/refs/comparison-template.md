# 分析模板：适配器 vs 网页版调用差异

排查「供应商调不通 / 适配器调用不对」时使用。目标：从抓包的真实请求出发，逐项定位与适配器（应用侧代码）的差异，**只改有据的差异，不猜测**。

## 输入
- 抓包文件 `capture-*.ndjson`（网页版真实请求）
- 适配器代码（应用侧发送的请求）

## 分析步骤

### 1. 明确要分析的操作
选定一次业务操作，例如：登录、新建会话、发送消息、查询列表。

### 2. 从抓包提取网页版请求（对照表 A）
对每个相关请求，记录：

```
方法   POST
URL    https://host/path?query
请求头  Cookie: a=...; b=...
       Authorization: Bearer ...
       X-Custom: ...
请求体  {"conversationId":"...","title":"..."}
状态   200 / 401 / ...
```

用 `node scripts/analyze.mjs <file> --json` 快速拿到端点表 + 关键头 + Set-Cookie + 跳转链。

### 3. 提取适配器请求（对照表 B）
读适配器代码，还原它实际发送的同一操作请求。

### 4. 逐项比对（差异清单 D）
按优先级检查：

| 检查项 | 说明 |
|--------|------|
| ① Cookie 名/值 | 名是否一致（如 `serviceToken` vs `xiaomichatbot_serviceToken`）；值是否带引号 |
| ② 请求头 | 是否缺 `Authorization`/`Cookie`/自定义 `X-*`；是否多了会被拒绝的头 |
| ③ query 参数 | 如 `?xiaomichatbot_ph=` 是否存在 |
| ④ body 结构 | 字段名/类型/必填是否一致 |
| ⑤ 方法 | GET/POST/PUT/DELETE 是否一致 |
| ⑥ 端点路径 | path 是否一致（可能是 v1/v2、命名差异） |

### 5. 定位认证层 vs 接口层
- 若**所有**接口 401 + `loginUrl` 指向 `sts/`/`pass/`：是认证问题（Cookie 名/值、STS 交换、签名头）。
- 若某接口单独报错（400/参数错）：是接口层（body/路径/参数）。
- 区分「接口可达性」与「认证是否通过」——先看 HTTP 状态，再看 body 的 `code`。

### 6. 结论与修复点（E）
对每一处差异给出：
- 差异描述
- 网页版证据（URL/头/body）
- 修复动作

### 7. 验证
用抓包拿到的**有效凭证**对修复后的接口实测，确认：
- 返回不再是 401
- body `code:0` / 预期结果

## 参考案例：Mimo
见 `SKILL.md`「参考案例：Mimo」。核心：接口/方法/URL/body 全对，唯一差异是 Cookie 名 `serviceToken → xiaomichatbot_serviceToken`，修正后 `code:0 成功`。

## 规则
- 每处差异必须有网页版录制证据，禁止凭空假设。
- 不向用户索要明文凭据；录制文件分析后按需清理。
- 修改后仅依据「网页版证据 + 实测结果」判定是否修复，不以适配器原实现为准。
